# AviUtl2（ExEdit2 2.1.16）功能分析与 Freya NLE 借鉴批次

分析日期：2026-11-05。代码基线：`8c1efccc`（`main`，0.7.0-rc.2 之后）。
二进制基线：`AviUtl2/aviutl2.exe` 2.1.16（PE32+ x86-64；Ghidra 项目
`AviUtl-reverse`，14,148 个函数）。同目录发行包附带 `aviutl2.txt`（操作说明）、
`style.conf`、`system.conf`、`effect.conf` 与各脚本示例。

目标：把 AviUtl2 的**功能能力**当作参照，判断哪些值得学、哪些不该照搬，并给出
在 Freya NLE（Rust + Slint + wgpu）里可落地、可验收的实施批次。界面部分已经由
[上一份分析](./2026-11-05-aviutl2-ui-analysis.zh-CN.md)覆盖，本文只谈功能与编辑模型。

## 1. 结论摘要

AviUtl2 不是"经典 AviUtl 加几个效果"，而是一次内部重写：内部格式改为
RGBA16bitFloat（乘算 α）与 PCM32bitFloat，渲染走 GPU，窗口改为单窗口内自由分组，
场景、对象、图层、效果的关系都重新定义过。对 Freya 最值得借鉴的是七件事，按
"用户每天会用到的频率 × 我们的缺口"排序：

1. **时间线帧标记（マーク）与备注**：在帧上打点、写备注、按标记前后跳转，并在
   标记列表里集中管理。
2. **图层设置**：对整层的媒体对象统一做坐标与音量偏移，并可改图层名与背景色。
3. **文本控制字符（制御文字）**：颜色、字号、字体、坐标、字距行距、显示速度/
   等待/清屏、注音、表情与内嵌脚本。
4. **参数参照式（参照式）**：一个参数可以引用同效果、同对象其它效果、指定图层
   或"上方/下方最近对象"的参数，并用 `@min`/`@clamp` 一类函数计算。
5. **对象与场景的工作流**：对象列表、场景标签（`\` 分层）与筛选、对象分组/解除。
6. **长任务与数据安全**：批量输出队列、完整备份历史（间隔、上限、可恢复）。
7. **设置层的可配置性**：逐项预设、追加/初始化默认值、菜单定义（顺序/层级/隐藏）。

不该照搬的部分同样明确：单文档单窗口、全自绘控件、Windows 专属插件 ABI、
"场景相关操作不支持撤销"（`aviutl2.txt` 明说）、固定像素的界面度量。

Freya 已经领先的地方也应保留：64 位与 GPU 合成、覆盖场景操作的撤销/重做、
多项目标签、包管理与权限、片段（`.freyafrag`）与 Exo 导入、Lua 表达式参数、
BPM 网格与吸附、涟漪/滚动/滑移等批量编辑工具。

## 3. 功能地图

### 3.1 项目与文件

`ファイル` 菜单的条目是项目语义：`プロジェクトを保存`（`0x486d48`）、
`別名で保存`（`0x486d28`）、`バックアップしたプロジェクト`（`0x486d60`）、
`最近使ったプロジェクト`（`0x486d80`）、`プロジェクトを閉じる`（`0x486d98`）、
`エクスポート`（`0x486cf8`）、`インポート`（`0x486d08`）、`ファイル出力`
（`0x486d18`）、`バッチ出力`（`0x4692a0`）、`終了`、`保存して終了`。

关键差异在"备份"：AviUtl2 把备份当成项目历史，而不是崩溃兜底。设置项
`自動バックアップ`（`0x468f50`）、`バックアップの間隔(分)`（`0x468f30`）、
`バックアップファイルの最大数`（`0x468f80`）、`バックアップファイルフォルダ`
（`0x45aeb0`）由 `バックアップ履歴の設定`（`0x487558`）统一管理，实现侧对应
`Edit::BackupHistory::autoBackupProject`（`0x4701c0`）与
`AutoBackup`/`AutoBackupInterval`/`AutoBackupFileMax`（`0x46e268`/`0x46e278`/
`0x46e5a0`）。

`情報` 菜单（`0x486c58`）集中放 `バージョン情報`、`パッケージ情報`、
`言語ファイル情報`、`スクリプト情報`、`プラグイン情報`（`0x486b68`–`0x486bd8`），
即"装了什么"是可查询的，而不是只写在日志里。

### 3.2 时间线编辑

`レイヤー編集` 的能力可以归成五组：

- **对象放置与选择**：对象按绝对帧放置；`Ctrl` 点击加选、`Ctrl` 双击选中同层、
  `Ctrl+Shift` 点击选中范围、`Ctrl` 拖动矩形框选、`Ctrl` 点图层名选中整层，
  以及按住 `Ctrl` 拖动跨层全选。
- **时间与中间点**：拖动开始/结束点时同组同时移动；`Shift` 拖动中间点会连带
  前后段；选中对象或中间点后方向键逐帧移动；分割/删除中间点的快捷键作用于
  当前选中的中间点。
- **图层操作**：点图层名切换显示；拖动图层名换序；点击选中后删除/重命名作用于
  整层；`Alt` 点图层名对其余层做同样切换；右键拖动滚动、`Ctrl` 右键拖动改缩放/
  行高。
- **帧范围**：`Shift` 移动显示帧进入范围选择，双击顶部范围条取消。
- **对齐与右键菜单**：`オブジェクト整列`（`0x486668`）、`オブジェクト複数選択`
  （`0x486650`）、`左側に詰める`/`切り取りして詰める`（`0x486440`/`0x486460`）、
  开始/结束帧对齐等；对齐以右键位置的对象为基准，受中间点与相邻对象限制。

命令清单（`0x485e88`–`0x4866a8`）还包含 `次のマークに移動`/`前のマークに移動`
（`0x485fc0`/`0x485fd8`）、`フレーム範囲選択`（`0x486310`）、
`オブジェクトのグループ化`/`グループ解除`（`0x486380`/`0x4863a0`）、
`オブジェクトのアンカー操作をロック`（`0x486418`）、
`カメラ制御の対象オブジェクトの有効・無効`（`0x4862e0`）等。

**帧标记**是独立的一组：`フレームをマーク`（`0x4567b8`）、
`マークのメモを変更`（`0x456818`）、`マークを削除`（`0x456830`）、
`現在のフレームをマーク`（`0x45fc68`），面板 `マークリスト`（`0x45fc58`）
由 `Component::MarkListComponent`（`0x45fca0`）实现；标记会画在图层编辑的
标尺上，并支持前后跳转。`MarkFrame`（`0x499128`）是配置里的标记帧键。

### 3.3 对象、效果与参数

- **效果顺序**：拖动效果名改变顺序；点击选中后的复制/粘贴/删除快捷键作用于
  效果项本身。实现侧有 `EffectSetting::cutEffect`/`cutAfterEffect`/
  `copyEffect`/`copyAfterEffect`/`pasteEffect`（`0x465fc0`–`0x466138`），即
  AviUtl2 支持"只复制当前效果"与"复制当前及之后"两种粒度。
- **逐项预设**：图标菜单可从当前设置创建预设，可选择"只存自身"或"存自身及
  之后的效果"；应用"自身及之后"时替换后续效果栈，应用时可只覆盖部分设置项。
- **初始值**：右键菜单可修改"新建对象/初始化时"的默认值，带媒体输入的还保存
  输出侧组合。
- **参照式**：数值项名称的右键菜单打开 `参照式を編集`（`0x463500`），
  入口在 `EffectItemNumberBase::showReferenceExpressionDialog`（`0x463530`）。
  语法允许 `X`（同效果其它项）、`ぼかし.範囲`（同对象其它效果）、
  `layer1.ぼかし.範囲`、`above.X`/`under.X`/`above2.X`/`レイヤー名.…`，
  支持 `X*2` 一类算式与 `@min`/`@max`/`@abs`/`@clamp`；`$` 展开为自身项名。
- **别名**：`エイリアスを作成`（`0x4557e8`）/`ファイルに保存`（`0x455800`），
  以 `.object` 文件保存当前对象或效果的设置，可再拖入或从菜单调用；
  对应 `EffectItemNumberBase::loadMovementAlias`（`0x463430`）等。
- **效果与对象的组合能力**：`画像合成`、`グループ制御`、`カメラ制御`、
  `シーンチェンジ`、`モーションブラー`、`部分フィルタ`、
  `クリッピングオブジェクト`、`上のオブジェクトでクリッピング`、
  `フレームバッファ` 都有独立对象/效果与明确的层级语义。
- **颜色**：`色設定` 面板支持多调色板、调色板命名，并把预设名加进颜色项的
  选择列表（`EffectColorPaletteControl::createPalette`/`renamePalette`，
  `0x457720`/`0x4577d8`）。

### 3.4 文本

`テキスト編集` 面板加一组控制字符（`aviutl2.txt` 第 470 行起）：

| 控制字符 | 作用 |
| --- | --- |
| `<#RGB>` / `<#文字色,影縁色>` / `<#red>` | 颜色，支持预设名 |
| `<s字号[,字体,样式,縁取り]>` / `<s+10>` / `<s*1.5>` | 字号与相对字号 |
| `<@字体[,装饰]>`、`<@+B>`/`<@-B>` | 字体与粗体/斜体/删除线 |
| `<$预设名>` / `<$>` | 应用文本预设 / 恢复默认 |
| `<r速度>` | 显示速度（逐字） |
| `<w秒>` / `<w*0.2>` | 等待，`*` 表示按已显示字数计时 |
| `<c秒>` | 等待后清屏 |
| `<p x,y,z>` / `<p+20,+40>` | 绝对/相对坐标 |
| `<gw字距>` / `<gh行距>` | 字距与行距 |
| `<tw>`/`<th>`/`<tr>` | 横/纵缩放与旋转 |
| `<&表情名>` | 表情图片 |
| `</>汉字<!0.4+>注音</>` | 注音（ルビ） |
| `<//注释//>`、`</>` | 注释与块分隔 |
| `<?lua?>` / `<?=函数?>` | 内嵌脚本 |

`テキスト編集` 里 `Ctrl+Space` 有输入补全：字体名、预设色、已注册表情、控制字符
模板；选中文字后 `Ctrl+加减` 插入字号控制字符、`Ctrl+方向键` 插入坐标控制字符。

### 3.5 场景

`シーンリスト`（`0x460018`，`Component::SceneListComponent`）是独立面板：
拖动改顺序；复制是**引用复制**；可把 Exo 当场景追加；场景名可设标签，标签名用
`\` 分隔即多层；标题栏可按标签筛选；图标按钮增删场景。

`シーンの設定`（`0x46e928`）与 `シーン名を変更`（`0x46e938`）管尺寸/帧率/时长/
网格等。`シーン再生`（`0x45f020`）是独立预览，可与编辑帧联动，也可把编辑窗口
切到同一场景。

`aviutl2.txt` 明说：场景相关（增删、网格、标记等）目前**不支持撤销**
（第 47–55 行「注意点」）。这是典型的"照搬会倒退"的地方。

### 3.6 素材、预览与直操纵

`メディアエクスプローラー`（`0x45aab2`）是文件浏览器，带书签
（`ブックマークに追加` `0x45acb0`）、应用数据目录入口与右键菜单；
不是"素材库"，素材库式管理由场景/对象承担。

`プレビュー編集` 的直操纵很完整：拖动移动、顶点缩放、`Ctrl+Alt` 移中心、
`Alt` 拖动改缩放、锚点 `Alt` 拖动绕 Z 旋转、旋转锚点（`Alt` 改深度轴、
`Alt` 双击回正）、相机控制右键拖动视角、`Ctrl+滚轮` 缩放、中键拖动平移。
`シーン再生` 里点击播放、拖动寻帧，`Alt` 双击把编辑窗口切到同一场景。

### 3.7 输出

标准输出是未压缩 AVI / PNG / JPG，YUV 走 WIC 与编解码设置；文件输出完成提示、
YUV 转换在 `ファイル出力の設定` 里关闭/开启。更关键的是**批量输出**：
`バッチ出力`（`0x486da0`）、`Dialog::BatchDialog::BatchItem`（`0x469110`）、
`Plugin::BatchProject`（`0x487cc0`）与 `Plugin::BatchService`
（`0x487eb0`–`0x488030`，含 `startOutputFile`/`stopCurrentBatch`/
`completeOutputFile`/`updateBatchProjectList`），配置键
`正常に完了したバッチを自動的に削除`（`0x469220`）、
`バッチ出力完了時の動作`（`0x469248`）、`BatchPostProcessType`（`0x48e1b8`）。
入口是各输出对话框里的"批次登録"按钮，输出设置可随项目保留。

### 3.8 设置

`設定` 菜单（`0x486b68`–`0x487610`）是一张能力表：

| 设置 | 字符串 | 对应实现 |
| --- | --- | --- |
| 快捷键 | `ショートカットキーの設定` `0x4874b0` | `Dialog::ShortcutKeyDialog` `0x46cea0` |
| 对象追加菜单 | `オブジェクト追加メニューの設定` `0x487610` | `MenuDefineDialog<Effect::EffectMenu>` `0x46b290` |
| 轨道条移动菜单 | `トラックバー移動メニューの設定` `0x4875f0` | `MenuDefineDialog<Effect::MovementMenu>` `0x46b400` |
| 时间制御菜单 | `時間制御メニューの設定` `0x4875d8` | `MenuDefineDialog<Effect::MovementPresetMenu>` `0x46b6e0` |
| 预设色菜单 | `プリセット色メニューの設定` `0x4875b8` | `MenuDefineDialog<Effect::PresetColorMenu>` `0x46b860` |
| 字体菜单 | `フォントメニューの設定` `0x4875a0` | `MenuDefineDialog<Media::FontDefineMenu>` `0x46b580` |
| 输入插件 | `入力プラグインの設定` `0x487588` | `InputPluginDialog` `0x46bda0` |
| 输出插件 | `出力プラグインの設定` `0x487570` | `OutputPluginDialog` `0x46a010` |
| 备份历史 | `バックアップ履歴の設定` `0x487558` | `AutoBackup*` |
| 缓存大小 | `キャッシュサイズの設定` `0x487540` | VRAM 资源/数据缓存 |
| 编解码 | `コーデックの設定` `0x487528` | YUV 压缩展开 |
| 文件输出 | `ファイル出力の設定` `0x487510` | 完成提示音、YUV 输出 |
| 共通操作 | `共通操作の設定` `0x487500` | 中键当右键、Alt+左键当右键 |
| 画面 | `画面の設定` `0x4874f0` | 高 DPI、优先高性能 GPU |
| 语言 | `言語の設定` `0x4874e0` | `.aul2` 语言文件 |

`MenuDefineDialog` 的五个特化说明"菜单定义"不是对象追加菜单的专属，而是所有
可枚举菜单的统一机制：顺序、层级（`\` 分隔）、显隐都可在设置里改。

### 3.9 扩展

脚本/插件可以增加动画效果、自定义对象、相机效果、场景切换、轨道条移动方式；
包与单文件都可拖到预览窗口安装，包信息里可卸载。字体与表情是"放文件即生效"，
不需要注册表或安装器。

## 4. 与 Freya NLE 的对照

基线 `8c1efccc`。判断列的含义：**保留**＝现状更好；**采用**＝值得照做；
**改造**＝照做但要换实现方式；**不做**＝不适合本项目。

| 能力 | AviUtl2 | Freya 现状 | 判断 |
| --- | --- | --- | --- |
| 内部精度 | RGBA16F、PCM32F | wgpu 管线，浮点合成 | 保留 |
| 场景操作撤销 | 不支持 | 场景增删改都进撤销栈 | 保留 |
| 单窗口分组 | 有，可分离/合并/标签 | 多窗口 + 项目标签 + 合并工作区（上一轮） | 保留 |
| 帧标记 + 备注 | 有（列表 + 前后跳转） | 无 | **采用**（B1） |
| 图层设置（整层偏移/音量） | 有 | 无层偏移；只有对象级 transform | **采用**（B2） |
| 图层名 / 背景色 | 有 | 仅 `Layer N`，无背景色 | **采用**（B2） |
| 文本控制字符 | 完整一套 | 纯文本 + 对象参数 | **采用**（B3，分批） |
| 参数参照式 | 跨效果/跨层引用 + 函数 | 只有 `=` Lua 表达式（AviUtl 1.x 风格） | **改造后采用**（B6） |
| 效果级复制/剪切/粘贴 | 有（自身 / 自身及之后） | 只有对象级剪贴板与效果排序 | **采用**（B4） |
| 逐项预设（存自身/自身及之后） | 有 | 效果级预设（`PresetStore`） | 改造后采用（B4） |
| 新建/初始化默认值 | 有，可按媒体组合 | 无 | 采用（B4） |
| 别名 `.object` | 有 | 无 | 不做（片段已覆盖大部分用途） |
| 对象列表 | 有 | 无 | 采用（B5） |
| 对象分组/解除 | 有 | 无 | 采用（B5） |
| 场景标签 + 筛选 | 有（`\` 分层） | 无 | 采用（B5） |
| 场景引用复制 | 有 | 场景对象 + 复制语义待核 | 改造后采用 |
| 批量输出 | 有 | 单次导出 + 进度 | **采用**（B7） |
| 备份历史 | 间隔/上限/可恢复 | 崩溃恢复快照（`RecoveryStore`），无历史版本 | 改造后采用（B8） |

## 5. 设计决定

### 采用

1. **帧标记是场景数据，不是界面状态**：随项目保存、随撤销回滚、按场景隔离。
   备注是标记的一部分；标记列表按帧排序，是导航入口而不是第二个时间线。
2. **图层设置是图层属性**：坐标/音量偏移作用在该层所有媒体对象上，相机控制
   对象不受影响（与 AviUtl2 语义一致）；图层名与背景色是同一份图层属性。
3. **文本控制字符做成解析层**：先支持不影响时序的颜色/字号/字体/坐标/间距/
   注音，再补 `<w>`/`<c>`/`<r>` 这类需要逐帧求值的控制字符。
4. **参照式复用表达式求值器**：把引用解析成"当前帧的参数值"，再交给现有 Lua
   表达式求值路径，避免第二套求值语义。
5. **批量输出是队列**：每个批次项保存项目路径 + 输出设置 + 覆盖策略，队列可
   暂停/取消/重排；渲染仍复用单次导出管线。
6. **备份历史是显式的版本列表**：在现有恢复快照之上加"按项目保留 N 份 + 可
   手动打点"，恢复走现有打开路径，不引入第二套项目格式。

### 改造后采用

- **对象分组**：AviUtl2 的组是选择与移动的联合体；在 Freya 里实现为"组 ID +
  组内对象集合"，只影响选择/移动/删除的原子性，不改渲染层级。
- **场景标签**：用 `\` 分层与筛选，但标签存成数组而不是解析字符串，界面再按
  层级折叠。
- **逐项预设**：复用 `PresetStore`，把作用域从"效果"扩展到"效果项"。

### 不做

- 全自绘控件与固定像素度量（无障碍与 DPI 会倒退）。
- 单文档单窗口（多项目标签更好）。
- 场景操作不进撤销栈（这是 AviUtl2 的已知短板）。
- Windows 专属插件 ABI（Freya 的扩展点是包与 Lua）。
- 缓存大小设置（后端自管，暴露给用户只会制造错误配置）。

### 7.2 B2：图层设置

AviUtl2 的 `レイヤー設定` 把图层名、背景色和整层坐标/音量放在一处；本轮按同一语义
落地，并把它接进预览与导出共用的求值计划。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `freya-nle-core/src/project.rs` | `SceneDocument.layerSettings` 与 `LayerSettingDocument`；归一化按图层排序去重、名称 64 字符、背景色规范成 `#rrggbb`/`#aarrggbb`、坐标限制 ±100000、音量 0–500%，全默认项不入库 |

| core | `bake_plan.rs` | 每帧求值时把图层偏移加到对象变换之后（组控制之后）；音量乘到音频计划；相机控制的目标层（`layerCount` 范围）与控制对象本身不参与偏移 |
| app | `workspace.rs` | `LayerSettingsInput`、`layer_settings`、`layer_settings_for`、`update_layer_settings`；颜色非法时拒绝并保留对话框，数值越界则夹紧，改回默认会删除条目不留下空记录 |

| i18n | `translations/{ja_JP,zh_CN}` | 9 条新文案 |
| 工具 | `tools/ui-snapshot` | 新增 `layer` 模式，时间线样例增加「Titles」图层名与蓝色背景 |

语义与取舍：

- **相机目标层**：AviUtl2 的说明是「不影响相机控制的目标对象」。这里用相机控制对象的
  `layerCount` 算出目标层范围，范围内的对象不叠加图层偏移；相机本身的渲染范围仍是
  整个场景，这与既有的 `CameraRenderPlan` 一致，属于已知简化。
- **控制对象**：相机、相机控制、组控制与帧缓冲对象保留自己的坐标，不被图层偏移
  推动；媒体对象（视频、图像、文本、图形、场景引用）才应用偏移。
- **音量**：图层音量是线性倍率，乘在对象音量之后；没有音频效果的对象也按倍率进入
  音频计划，与 AviUtl2 的"整层音量"一致。
- **颜色**：时间线行用 38% 透明度铺底，图层头只画 3px 色条，避免亮色背景压过对象
  文字；这是对 AviUtl2 全底色的一次可读性改造。

验证：

- `cargo test --workspace --all-features` 通过（core 168、app 255、desktop 56）；
- 本 crate 的 `cargo clippy --all-targets --no-deps -- -D warnings` 与
  `cargo fmt --all -- --check` 干净；
- 离屏渲染深色/浅色时间线与图层设置窗口：图层头显示「3 Titles」，第 4 行出现蓝色
  铺底且对象文字可读；对话框在 460×430 下字段与按钮完整；
- `--frames 30` GPU 冒烟（Apple M5）通过，验证项目带图层名、背景色与偏移，
  `wgpu_errors: []`。

边界：图层偏移在组控制之后叠加，因此"组控制包含该层"与"图层偏移"会同时生效；
剪裁对象与上层剪裁的蒙版对齐没有单独修正。相机 `layerCount` 仍只用于偏移排除，
不改变相机本身的渲染范围。

边界与风险：

- **只改样式，不改排版位置**：`<p>` 坐标、`<gh>` 行距、字体族与粗斜体仍是第二批；

### 7.9 B8（第一批）：备份历史

AviUtl2 的 `バックアップ履歴` 保留项目的多个历史版本。Freya 已有崩溃恢复快照，
但它只保护"尚未保存的工作"，而且项目关闭后会被清理；保存过的版本一旦被覆盖就没有

| 层 | 位置 | 改动 |
| --- | --- | --- |
| app | `backup.rs`（新增） | 按项目路径的 SHA-256 前 8 字节分目录；每次保存写一份带毫秒时间戳的副本（原子写）；保留最近 N 份并删除更旧的；文件名校验拒绝路径穿越；默认上限 20 |
| app | `lib.rs` | `ApplicationModel` 持有 `BackupStore`；直接保存与 Save As 成功后写入副本；`backup_entries`、`remove_backup`、`open_backup_as_project`、`backup_errors`、`set_backup_history` |
| ui | `backup-history.slint`（新增） | 列出时间与大小，每行有 Open/Delete，空列表有提示；关闭按钮 |
| ui | `main.slint`、`timeline.slint`、`callbacks.rs`、`lifecycle.rs` | File 菜单「Backup History...」在预览与时间线两个窗口一致；打开时按当前项目读取列表，恢复后切到新的未保存工程 |
| i18n | `translations/{ja_JP,zh_CN}` | 4 条新文案 |
| 工具 | `tools/ui-snapshot` | 新增 `backup` 模式，渲染两行样例 |

语义与取舍：

- **保存即备份**：本批按"每次成功保存"留版本，而不是按分钟轮询；这与用户的直觉
  一致，也避免后台线程。AviUtl2 的间隔备份留给 B8.5（或复用现有恢复定时器）。
- **恢复不覆盖**：副本以未保存、dirty 的工程打开，名称带 `(backup)`；用户必须显式
  Save As 才会落盘，和恢复快照的语义一致。
- **淘汰**：目录里按文件名（毫秒时间戳）从新到旧排序，超过上限删除最旧的；同一毫秒

- **失败不阻断保存**：写副本失败只记入 `backup_errors`，保存本身仍然成功；备份是
  附加保护，不应让正常保存失败。
- **项目移动**：目录键是项目路径的 SHA-256 前缀；移动或改名项目会从新的历史开始，
  旧副本留在原键目录，不会自动迁移。
- **后续**：界面里的开关/上限/手动打点已在 §7.12（B8.5）补齐；跨项目查看在 §7.31、
  容量策略在 §7.34、目录位置在 §7.35 补上。

### 7.11 B3.5：文本显示时序

AviUtl 的文本动画大量依赖 `<r>`（显示速度）、`<w>`（等待）与 `<c>`（清屏后切换）。
上一批只处理样式，这些指令仍按字面显示；本批把时序接进逐帧求值，渲染器无需再改。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `text_control.rs` | 文本被切成块与带显示时间的字符：`<r>` 设置每秒字符数（`<r>` 恢复对象速度，`<r0>` 立即显示）；`<w>` 推迟后续字符（`*` 形式乘以已显示字符数）；`<c>` 在等待后清空当前块并开启下一块，同时吞掉紧随的换行 |
| core | `bake_plan.rs` | `TextRenderPlan` 新增 `runs_authoritative`；文本按 `relative_frame / fps` 取当前时间生成可见 runs，对象 `speed` 参数作为基准速度；计数器仍是单 run |
| core | `catalog/objects/TextObject.json`、`i18n/effect-metadata.json` | 文本对象新增「表示速度」参数（0–1000），并补英/中标签 |
| render | `text.rs` | 只要 `runs_authoritative` 或 runs 多于一个就用 run 布局；runs 为空（被 `<c>` 清空）时输出 1×1 透明帧，不再把原始标签画出来 |
| api | `bake_plan.rs` | `TextRun`/`TextRenderPlan` 的构造点补齐新字段 |

语义与取舍：

- **速度**：`<rN>` 为每秒 N 个字符（N=0 即时）；等待与清屏按"当前显示游标"计时，而不是
  按对象起点，因此 `<r1>abc<c2>` 在 3 秒后仍显示 2 秒再清空。
- **清屏**：块在清空时刻结束，下一块从该时刻开始；`<c>` 的延时相对当前游标，`<c*F>`
  乘以当前块已显示字符数；`<c>` 直接清空。
- **字符计数**：换行不计入"已显示字符数"，但换行本身也有显示时间（打字机换行会多等一
  个字符间隔）；`<w*>`/`<c*>` 使用非换行字符数。
- **对齐**：文本按当前可见内容重新排版，居中/右对齐的文本在打字过程中会随字数移动；
  AviUtl 同样没有额外锚点控制，`<p>` 批次再补固定坐标。
- **边界**：本批不含字体/样式切换、`<p>` 坐标、`<gh>` 行距、注音、表情与脚本；这些
  仍按字面显示。

验证：

- `cargo test --workspace --all-features` 通过（core 189、app 269、desktop 57、render 40、preview 25）；
- 解析器 16 项测试覆盖时序：速度逐字显示与 `<r0>`、等待与 `*` 形式、清屏换块、清屏后
  吞换行、时序与颜色组合、对象基准速度；
- 求值计划测试以 10fps 验证同一文本在第 0/5/10 帧分别显示 `a`/`ab`/`abc`，以及
  `one<c1>two` 在 1 秒时切到 `two`；
- `clippy --no-deps` 与 `fmt --check` 干净；GPU 启动冒烟无 wgpu 错误。

### 7.13 B3.6（第一批）：字体、样式与注释

AviUtl 的文本控制字符还能在中途切换字体、加粗/斜体/删除线，并用注释与块分隔组织
长文本。此前 `<@...>` 一律按字面显示，长文本里的注释也会出现在画面上；本批补齐这
三类，坐标、行距、注音、表情与内嵌脚本留给 B3.7。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `text_control.rs` | `TextRun` 新增 `font_family`/`bold`/`italic`/`strikethrough`；`TextBaseStyle` 携带对象的字体族与粗斜体作为基准；解析 `<@Family[,3BI]>`、`<@>`、`<@+B>`/`<@-B>`，扩展 `<sNN,Family,BI,outline>`；`<// … //>` 与 `</>` 不产生字符；跨 run 的分段条件同时比较字体与样式 |
| core | `bake_plan.rs` | 计数字符串的 run 补齐新字段；`fontBold`/`fontItalic` 进入基准样式，`<@>` 因此能回到对象设置 |

语义与取舍：

- **装饰数字**：第二段的数字 0–6 是 AviUtl 的阴影/描边样式。本批接受数字并据此重置

- **注释与块分隔**：注释可跨行，注释里的 `>` 不会截断指令；`</>` 只切块边界，当前

- **粗斜体的实现**：靠 fontdb 的查询找同族的 Bold/Italic 变体，没有变体时退到最近

- **删除线位置**：按字号比例放在基线上方 32% 处、厚度为字号的 6%，横线覆盖整个 run

- **API 影响**：`TextRun` 增加了四个公开字段，属于 0.7-rc 的字段追加；外部若自行

### 7.16 B6（第一批）：参数参照式

AviUtl2 的参照式让一个参数读取别的参数再计算：同一效果的 `X`、同一对象的
`ぼかし.範囲`、`$` 代表自身参数名，`@min/@max/@abs/@clamp` 包住运算。Freya 只有
导入 Exo 时带进来的 `=Lua` 表达式，界面上没有任何入口。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `bake_plan.rs` | 效果新增 `expressions`（存放在效果的额外字段里，与数值分开）；解析时先做引用替换再交给现有 Lua 求值器；支持同效果裸名、同对象 `效果名.参数`/`效果ID.参数`、`$` 展开与 `@min/@max/@abs/@clamp`；循环引用与无法解析的引用保留字面值与数字回退 |
| core | `expression.rs` | Lua 快捷环境补 `clamp(value, low, high)`，与 `@clamp` 对应 |
| core | `timeline_state.rs` | 新增 `SetEffectExpression` 请求：参数必须存在（值或关键帧），写入/清除效果额外字段里的 `expressions`，空表时移除该字段 |
| app | `workspace.rs` | `set_effect_expression`、`effect_expression`；表达式与数值分存，清除后回到用户原来的数字 |
| ui | `object-controls.slint`、`object-settings.slint` | 效果右键菜单新增「参数参照式...」；对话框含参数下拉、表达式输入、说明与 清除/取消/保存；切换参数时读取已存的表达式 |
| ui | `object_settings.rs`、`callbacks.rs` | 从对象设置投影里取参数的本地化标签；保存/清除走工作区命令并刷新 |
| 工具 | `tools/ui-snapshot` | `UI_SNAPSHOT_EXPRESSION=1` 渲染对话框 |
| i18n | `translations/{ja_JP,zh_CN}` | 6 条新文案 |

语义与取舍：

- **表达式与值分开存**：AviUtl2 的参数既有当前值又有参照式；分开存的好处是清除参照式
  后回到原来的数字，而不是回退到 0。导入的 `=Lua` 仍按参数值里的字符串读取，两套
  写法都被同一条求值路径处理。
- **引用先替换，再交给 Lua**：`X*2 + 1` 变成 `3*2 + 1`，`@clamp(X,0,20)` 变成
  `clamp(3,0,20)`，剩下的算术交给已有的沙箱 Lua 求值器，避免第二套运算符优先级与
  函数语义。
- **解析不了的引用保持字面**：本批只覆盖同一对象内的引用，`layer1.X`、`above.X`、
  `under2.X` 与图层名留给 §7.17；整条表达式解析失败时参数保留原来的数字。
- **循环引用**：`a = b+1`、`b = a+1` 在递归时检测到回边即放弃，两个参数都保留原值，
  不会把进程卡住。
- **求值时机**：每帧在 `prepare_numeric` 之后、参数被读取之前解析一次，预览、导出与
  音频计划因此拿到同一份结果。
- **行内标记与入口**：带参照式的参数在设置列表里以 `ƒ` 后缀显示，并可在数值行的标签
  菜单里直接设置/清除（§7.26）；效果右键菜单的「参数参照式...」保留为批量挑选入口。
  `ObjectControl::expression` 由 `object_settings` 投影带出。
- **尚未做**：参数名里含点号的转义、行内函数以外的 Lua 库。

### 7.17 B6（第二批）：跨层引用

上一批把引用限制在同一对象内，`layer1.X`、`above.X`、`under2.X` 与图层名都只能
保持字面。本批把求值提升到场景级：先让每个活动对象算好自己的本帧数值，再统一解析
引用，因此引用可以跨层、跨对象，也仍然走同一条 Lua 求值路径。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `bake_plan.rs` | 新增 `ExpressionScene`：收集本帧活动对象，按（对象,效果,参数）缓存解析结果与访问集合；引用替换支持 `layerN`、`above`/`under`（可带层数，如 `above2`）、图层名、`Effect.$`，跨对象时默认按效果显示名或 ID 找到"同名效果"；解析结果在读取参数前写回各效果 |
| core | `bake_plan.rs` | `LayerSetting` 带上图层名，测试输入 `SceneInput` 接受 `layerSettings`，文档路径与测试路径共用同一份解析 |
| ui | `object-settings.slint` | 对话框说明改为支持 `above.X`、`layer1.X`，删掉"尚未解析"的提示 |
| i18n | `translations/{ja_JP,zh_CN}` | 更新 1 条说明、删除 1 条过期提示 |

语义与取舍：

- **场景级解析**：引用可能指向别的对象，逐对象解析拿不到对方数值；现在 `compute_output`
  在准备完所有活动对象的数值后统一解析一次，缓存与循环检测跨对象共享。
- **层序规则**：`above`/`under` 按"有活动对象的层号"排序后取第 N 个，而不是按层号
  连续加减——AviUtl2 里中间的空层不应影响"上面一个对象"的含义。
- **同层多对象**：同一层在同一帧有多个对象时取活动列表里的第一个；时间线通常不允许
  这样重叠，这里记录为边界而不是猜测。
- **同名效果**：`above.X` 这种省略效果名的写法，先按显示名、再按效果 ID 在目标对象上
  找与引用方相同的效果；找不到时整条表达式保留字面。
- **图层名**：来自场景的图层设置；重名时取层号较小的那个（BTreeMap 顺序），未命名的
  图层不能按名字引用。
- **未变**：仍然复用 Lua 求值器，函数仍是 `@min/@max/@abs/@clamp`；参数行还没有
  "带参照式"的标记。

验证：

- core 测试覆盖：`layer1.Blur.size` 与图层名 `Titles.Blur.size` 的跨层引用、

### 7.18 B3.7（第一批）：行距

AviUtl 的 `<gh[行間]>` 在文本中途改变行距，`<gh>` 恢复对象设置。此前每一行都用
全局行距，行内写 `<gh>` 只会照字面显示。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `text_control.rs` | 解析 `<ghNN>`（0–4096，`<gh>` 回到对象行距），run 新增 `line_spacing`；分段条件把行距纳入比较 |
| core | `bake_plan.rs` | 对象 `lineSpacing` 进入基准样式（0 表示自然行距），文本 run 透传 |
| render | `text.rs` | 行基线改为逐行累加：每一行的间距取该行最后一个设置了 `<gh>` 的 run，否则用对象行距或自然间距；逻辑高度按最后一行基线 + descent 计算 |

语义与取舍：

- **取行尾的值**：一行里可以多次出现 `<gh>`，决定下一行间距的是这行结束时生效的
  值——与"从这里开始改变行距"的直觉一致，也避免一行中途换行距造成的锯齿。
- **0 的语义**：`<gh0>` 被夹到 0 并视为"没有自定义"，仍回退到对象行距；这与
  `<gh>`（空值恢复对象设置）在视觉上等价。
- **逻辑高度**：背景与画布裁剪用最后一行基线加 descent，而不是首行高度加行数乘
  固定间距；行距变大时背景会跟着变高。
- **未做**：`<p>` 坐标、注音、表情与脚本仍是 B3.7 的后续；`<tw>/<th>/<tr>` 字符
  变形也不在本批。它们需要按块旋转或第二套布局，留到有明确参照时再做。

### 7.19 B3.7（第二批）：`<p>` 坐标

`<pX,Y>` 把后面的文字放到指定坐标，`<p+10>` 相对移动，`<p>` 回到正常排版。此前这些
标签按字面显示，AviUtl 文本预设里依赖坐标的版式无法复现。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `text_control.rs` | `TextAnchor`（`Flow`/`At`/`Reset`）进入 `TextRun` 与基准样式；解析 `<pX[,Y[,Z]]>`：带符号为相对上一位置，空字段沿用上一坐标，`<p>` 复位；坐标夹紧 ±32768，Z 接受并校验但不参与排版；分段条件包含锚点 |
| render | `text.rs` | 行结构带锚点：`<p>` 开一条新行，锚定块内的换行沿同一 x 向下推进；普通行仍按对齐与流式基线排布；逻辑宽高覆盖所有锚点 |

语义与取舍：

- **坐标含义**：`Y` 是该行文字框的顶部，基线为 `Y + ascent`；`X` 是该行左边缘，
  锚定行不再应用对象的水平对齐（坐标本身就是对齐结果）。这与 AviUtl 的像素坐标
  一致，但"基线还是顶边"没有官方说明，这里取顶边并写进实现记录。
- **相对与继承**：`<p+10,-20>` 相对上一个锚点；`<p,40>` 只改 Y；`<p>` 回到正常流。
  坐标复用上一个位置而不是回到 0，避免连续相对指令跳回原点。
- **锚定块内的换行**：`<p500,100>` 之后的换行保持 x=500，baseline 按该块自己的行距
  递增；`<p>` 之后的文字重新走普通流，普通流有自己的基线游标，两者互不覆盖。
- **负坐标与越界**：允许负坐标（文字可能落在原点左上），栅格范围由字形包围盒决定，
  不会裁掉；超过 ±32768 的坐标被夹紧。Z 仅校验，3D 文本不在本批。
- **未做**：注音、表情与内嵌脚本，以及 `<tw>/<th>/<tr>` 字符变形。

验证：

- `cargo test --workspace --all-features` 通过（core 201、app 273、desktop 62、render 44、preview 25）；
- core 测试覆盖绝对/相对/空字段/复位/非法写法；
- render 测试把第二个 run 锚到 (180,160)，帧宽高都比流式布局大 100px 以上；
- `clippy --no-deps` 与 `fmt --check` 干净；
- GPU 冒烟仍未取到帧（`main_frames: 0`、`wgpu_errors: []`，显示休眠），与 §7.18
  记录的现象一致，因此不宣称通过。

### 7.20 B3.7（第三批）：字符纵横比

`<twN>` / `<thN>` 改变文字的横向/纵向比例，`<tw>` / `<th>` 恢复 1.0。此前它们按字面
显示，压缩或拉长文字的预设无法复现。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `text_control.rs` | `TextRun` 与基准样式新增 `x_scale`/`y_scale`；解析 `<twN>`/`<thN>`（0–100，空值回到 1.0）；分段条件包含比例 |
| render | `text.rs` | 塑形后按比例缩放字形坐标、`y_offset` 与行内推进宽度；`GlyphOutline` 在字体单位阶段乘以纵向比例，横向比例同时作用于字距 |

语义与取舍：

- **作用于整段**：比例作用于 run 的字形位置与字距，而不只是轮廓，因此 `<tw0.5>`
  会同时收窄字宽与字距；这与"横向压缩整段文字"的直觉一致。
- **不回绕**：`<tw>` 只恢复横向，纵向保持之前的值；这与 `<gh>`/`<gw>` 的逐项复位
  规则一致。
- **`<tr>` 未做**：旋转需要把整段字形绕一个公共轴旋转，涉及字形位置与轮廓的共同
  变换，容易做出与 AviUtl 不一致的"每字自转"；本批只做比例，旋转留给后续。
- **行高不变**：纵向比例只影响墨迹，不改变行推进；需要更大行距仍用 `<gh>`。

### 7.21 B3.7（第四批）：`<tr>` 旋转

`<trN>` 旋转文字（带符号为相对当前角度，`<tr>` 恢复 0°）。上一批实现了 `<tw>/<th>`
比例，旋转需要字形位置与轮廓一起变换，单做轮廓会变成"每字自转"。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `text_control.rs` | `TextRun`/基准样式新增 `rotation`；解析 `<trN>`、`<tr+N>`、`<tr>`（±3600 夹紧）；分段条件包含角度 |
| render | `text.rs` | `GlyphOutline` 在屏幕坐标阶段绕 run 起点旋转，因此字形位置与轮廓一起转；删除线在旋转时跳过（横线无法表达旋转后的位置） |

语义与取舍：

- **轴心取 run 起点**：AviUtl 没有说明旋转轴，这里取"该 run 在基线左端的起点"，让整段

- **屏幕坐标旋转**：角度按屏幕坐标（y 向下）顺时针为正，与 `<tr90>` 把文字转向下的

- **删除线**：旋转后仍按水平线画会横穿字形，故跳过并在文档中记录。
- **未做**：注音、表情、内嵌脚本仍是 B3.7 的后续。

### 7.22 B3.7（第五批）：注音（ルビ）

`</>漢字<!>かんじ</>` 在汉字上方标注假名，`<!0.4>` 指定比例，`<!+>` 让行距把注音
算进去。此前整串按字面显示，日文标题基本无法复现。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `text_control.rs` | 解析 `</>…<!…>…</>`：`RubyRun`（块号、基文/注音、比例、是否扩展行距）进入 run 与基准样式；`</>` 开/闭块、`<!opts>` 切到注音；未闭合或孤立的指令按字面处理；比例夹紧 0.05–4 |
| render | `text.rs` | 基文照常排版；注音按 `基文字号 × 比例` 单独塑形，居中放在基文横向跨度上方（基线 = 基行基线 − 基文上升 − 间隙 − 注音下降）；`<!+>` 把注音高度加到上一行的行推进；注音与基文共用颜色/描边/阴影路径 |

语义与取舍：

- **块内逐段样式**：注音文本本身可以带 `<#>`、`<gw>`、`<s>` 等指令，按 run 保留各自
  样式再拼起来，示例里的 `<!0.4><gw8><#ff8888>じかんちょうせい` 因此可用。
- **居中而非逐字对齐**：把整段注音居中压在整段基文上；AviUtl 会按字数分配，这里在
  长注音时会略出界，记录为近似。
- **行距扩展**：`<!+>` 的注音高度加到"上一行"的行推进上，让下一行避开注音；首行的
  注音仍可能高出原点，由字形包围盒把画面向上扩展。
- **跨行注音**：一个块被换行拆开时，注音放在首个基文所在行；文档记录该边界。
- **未做**：表情 `<&name>` 与内嵌脚本 `<?…?>`。

验证：

- `cargo test --workspace --all-features` 通过（core 204、app 273、desktop 62、render 47、preview 25）；

- render 测试确认注音让帧向上变高、`<!+>` 行距不会比不扩展矮；

### 7.23 B7（第二批）：批次项绑定场景

第一批的批次项只有帧范围，导出多个场景时仍要手动切换场景再登记。AviUtl2 的批次项
指向具体的项目/场景，本批把场景一起存进条目。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| ui | `batch.rs` | `BatchItem` 增加 `scene`；JSON 读写带上 `scene`（缺失时按 1 处理）；队列记录批次开始前所在场景，结束后取回 |
| ui | `export.rs` | 登记时取当前场景与名称，行标签变成「场景名 · 文件名」；开始前切到条目场景、结束后（完成/停止/取消）切回原场景 |

语义与取舍：

- **切场景再读工程**：`begin_batch_item` 先 `switch_scene`，再读取导出工程与时长，
  因为场景时长决定帧范围是否有效；找不到场景时 `switch_scene` 返回 false，条目按
  当前场景继续，失败信息由导出管理器给出。
- **恢复时机**：全部完成、手动停止、取消确认三条路径都会恢复原场景；暂停/继续不
  恢复，因为队列还要接着跑。
- **标签**：场景名参与标签，列表里能直接看出这一项导出哪个场景；名称过长仍按 120
  字符截断。
- **边界**：条目仍不绑定项目文件（跨项目批次未做），场景在登记后被删除时按当前场景
  处理。

验证：

- `cargo test --workspace --all-features` 通过（core 204、app 274、desktop 63、render 47、preview 25）；
- `batch.rs` 测试覆盖场景号往返、缺省值、`remember_scene`/`take_restore_scene` 的消费语义；
- `clippy --no-deps` 与 `fmt --check` 干净；`--frames 20` 启动冒烟 `main_frames: 3`、

### 7.28 B3.7（第七批）：内嵌脚本 `<?...?>`

文本里的 `<?...?>` 在每一帧求值，输出替换整段指令。AviUtl2 的语义在二进制里可以
逐条确认，官方文档（控制字符的「スクリプト」一节与 Lua 变量表）也给出了一致的
说明；本批按这两边实现，而不是按推测：

- `0x1404599a8` 的正则 `<\?([^\x00]*?)\?>` 决定块边界（本实现用同样的"第一个
  `?>`"规则，未闭合时保留字面）；
- `FUN_1401af8c0` 在块首是 `=` 时删掉 `=`，改写成 `mes(<余下内容>)` 再交给脚本
  宿主，因此 `<?=expr?>` 不是"表达式求值"，而是 `mes(expr)` 的语法糖；
- `0x140480c60` 的 `mes(` 与 `0x140490058` 起的字段表（`time`、`totaltime`、
  `totalframe`、`framerate`、`screen_w`、`screen_h`、`effect_layer`、
  `originframe`、`frame_s`、`frame_e`、`ox`、`oy`、`z`、`rx`、`ry`、`rz`、`oz`、
  `scene_id`、`index`、`num`、`h`、`id`、`effect_id`）说明脚本通过 `mes()` 输出，
  `obj` 带的是对象与时间信息。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `expression.rs` | `TextScriptClock`（时间、总时长、帧、总帧、帧率）与 `expand_text_scripts`：逐块替换，`=` 块改写成 `mes(...)`；`TEXT_SCRIPT_PRELUDE` 建 `__text` 收集器、`mes` 与 `setfenv` 环境；失败保留字面 |
| core | `bake_plan.rs` | `text_render_plan` 先展开脚本再 `parse_text_runs_at`，脚本输出照常参与颜色、字距、`<r>/<w>/<c>` 计时 |

语义与取舍：

- **输出靠 `mes()`**：与 AviUtl 一致；脚本只 `return` 不 `mes` 时该块输出为空，因为
  AviUtl2 的宿主只取 `mes` 累积的字符串。`obj.mes(text)` 与 `mes(text)` 等价，两种
  写法都提供（官方 Lua 文档把 `obj.mes` 列为正式形式，`mes` 是省略写法）。
- **每块一个环境**：`setfenv(1, __env)` 让脚本里的赋值落在临时表，不污染共享 VM，
  避免上一个对象/上一帧的全局变量漏进下一个脚本；`_G` 仍可读，`math`/`string` 可用。
- **只读的一部分 `obj`**：官方文档把 `x/y/z`、`w/h`、`screen_w/h`、`framerate`、
  `frame/time`、`totalframe/totaltime`、`layer/index/num`、`id/effect_id`、
  `frame_s/frame_e`、`effect_layer/originframe/scene_id` 标为只读（ReadOnly ○），
  其余 `ox/oy/oz`、`rx/ry/rz`、`cx/cy/cz`、`sx/sy/sz`、`zoom/aspect/alpha` 可写，
  官方示例 `<?obj.rz=obj.time*360?>` 就是改写对象。本批只提供只读时间字段；可写变换
  在 §7.39 补上（`cx/cy/cz`、`sx/sy/sz`、`aspect` 仍未提供）。
- **失败保留字面**：语法错误、运行时错误、超长（>10 000 字符）都让整块原样显示，
  作者能看到是哪一条没跑起来；AviUtl2 出错时的具体呈现未在二进制里确认，这里选了
  更保守、可诊断的一种。
- **尚未暴露的只读字段**：本批只给时间四件套与 `framerate`；`layer`、
  `frame_s/frame_e`、`effect_layer`、`originframe`、`screen_w/h`、`scene_id` 在
  §7.29 补齐，`w/h` 与 `index/num/id/effect_id` 仍留在 B3.7 后续。

验证：

- `cargo test --workspace --all-features --locked` 通过（core 209、app 275、
  desktop 64、render 48、preview 25）；
- core 测试：`<?=4+8?>` → `12`、`string.format` → `05`、`<? mes(obj.time) ?>` →
  `1.5`、`obj.mes` 与多条 `mes` 拼接、`totaltime/totalframe`、失败与未闭合保留
  字面、两个块之间全局变量不串；
- bake 测试：`A<?=2+3?>B<#ff0000>C` 在帧计划里成为 `A5B` + 红色 `C`；10 fps 下
  第 15 帧的 `math.floor(obj.time)` 为 `1`，`obj.totalframe` 为 `60`；

### 7.36 B3.6（第二批）：`<s...,縁取りサイズ>` 的每段描边

§7.13 记录过一处遗留：`<s48,Meiryo,6BI,3>` 的第四段是每段的描边宽度，当时被"接受
但忽略"，描边一律沿用对象设置。官方手册「サイズの変更」一节明确第四段就是

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `text_control.rs` | `TextRun` 与 `TextBaseStyle` 新增 `outline_width: Option<f32>`；`<s...>` 的第四段解析为 0–512 的宽度，空段表示"回到对象宽度"，非法或负数让整条指令按字面显示；`<$>` 复位时一并还原 |
| render | `text.rs` | `RunPath`/`ShapedSegment`/`RunSegment` 携带该值；描边宽度按 run 取 `run.outline_width.unwrap_or(plan.outline_width)`，留白按**所有 run 的最大值**计算，因此粗描边不会被画布裁掉；`validate_plan` 拒绝非有限值与超过 512 的宽度 |
| api | `api.rs` | `TextBaseStyle` 导出（上一批新增的公开字段需要它） |

语义与取舍：

- **`None` 是"跟随对象"**：只有显式写了第四段才替换宽度，因此对象级描边设置仍然

- **`<s>` 复位**：裸 `<s>` 回到对象字号，同时也回到对象描边宽度，与手册"恢复初始

- **失败即字面**：第四段不是数字、为负、或超过 512 时整条 `<s>` 按字面显示，不做

### 7.37 B3.7（第十批）：表情按图片比例占位

§7.25 把每个 `<&name>` 画进"字号见方"的格子，因此宽图与高图都会留白，行宽也与
AviUtl 不同。本批让格子按图片自身的宽高比推进。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| render | `text.rs` | `EmojiDraw` 从 `size` 改为 `width`/`height`；新增 `emoji_aspect(name)`（取宽高比，缺图或非法尺寸回退 1.0，夹在 0.05–20）；塑形阶段的格子宽度改为 `font_size × aspect`，行宽与换行跟着变；绘制时用单一缩放把图片填满格子，不再居中留白；可视范围按格子的宽高记录 |

- **推进宽度随图片**：AviUtl 按图片像素比例推进，本文基准也如此；因此宽图会占更多
  横向空间，行宽、居中对齐与换行位置都会随之变化。
- **高度仍是字号**：图片按字号等比缩放，`height = font_size`、`width =

- **缺图回退方形**：与之前一致，找不到图片或尺寸非法时按 1:1 占位，保证排版稳定，

- **比例夹紧**：0.05–20 的上限防止极端图片（1×4096）把栅格尺寸推到上限之外。
- **测试目录共享**：`EMOJI_DIRS` 是进程级静态，新增的第二个表情测试如果各建目录会
  互相覆盖；现在两个测试共用 `emoji_test_directory()`，这也是并行测试下唯一稳定的

| ui | `object-controls.slint`、`object-settings.slint` | 效果菜单在「清除默认值」之后新增「保存为该对象的默认值 / 清除该对象的默认值」 |

语义与取舍：

- **两层默认值**：效果默认值（按效果 ID，任何对象获得该效果时都生效）与对象默认值
  （按对象类型，只影响新建的该类对象）。同时存在时对象类型优先，因为用户明确为
  "这个对象"做了取舍。
- **只收输入与输出**：只取 `transform` 与对象自身效果；用户后加的 `blur` 之类仍属
  效果默认值，不会被对象默认值收进去。
- **按效果整份替换**：同一个效果再次保存时它的参数整份覆盖，而不是逐键合并——逐键
  合并会保留目录里已经删掉的参数。
- **内容与文件仍排除**：新文本不该重复上一段文字，新媒体不该指向旧文件；这一点与

- **合并方向**：在插入前一次性并表，插入路径本身不感知对象默认值，于是预览、脚本

### 7.39 B3.7（第十一批）：文本脚本可以写对象变换

官方 Lua 文档的变量表把 `ox/oy/oz`、`rx/ry/rz`、`zoom/aspect/alpha` 标为可写，并给出
示例 `<?obj.rz=obj.time*360?>`：脚本改写对象，渲染按改写后的值执行。§7.28 只提供了
只读字段，本批补上写回。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| core | `expression.rs` | 新增 `TextScriptTransform`；`TextScriptClock` 带上对象变换；`begin` 把 `ox/oy/oz`、`x/y/z`、`rx/ry/rz`、`zoom`、`alpha` 放进 `obj`；`finish` 读回可写字段，非有限值整体丢弃；`expand_text_scripts` 返回 `(文本, 变换改动)`，未改动返回 `None` |
| core | `bake_plan.rs` | `text_render_plan` 拿到 `&mut EvaluatedTransform`，脚本改动写回该帧的变换；组控制与图层偏移改为在脚本之后叠加 |

语义与取舍：

- **读写同一张表**：一个对象的多个 `<?...?>` 块共享同一份 `obj`，因此第一个块写的值
  第二个块读得到，等价于"每帧跑一段脚本"。
- **`zoom` 是倍率**：Lua 侧 `zoom` 以 1.0 为等倍，内部 `scale_percent` 以 100 为等倍，
  转换在 `begin`/`finish` 两处各做一次。
- **只报告真实改动**：只打印不写字段时返回 `None`，对象沿用变换管线的结果，避免
  "读一下就冻结"。
- **非数值忽略**：`obj.alpha='x'` 这类写入留在表里（脚本自己能读回），但不会应用，
  对象保持原不透明度；任一可写字段非有限时整份丢弃。
- **叠加顺序**：脚本只碰对象自身变换；组控制与图层偏移在脚本之后叠加，所以脚本写
  `ox` 不会绕过组与层的语义。
- **未做的部分**：`aspect`（没有对应的对象参数）、`cx/cy/cz`、`sx/sy/sz` 仍未提供；
  `obj.effect()`/`obj.draw()`/`obj.setfont()` 这类"脚本驱动渲染"不在本批范围。

验证：

- `cargo test --workspace --all-features --locked` 通过（core 215、app 283、
  desktop 66、render 50、preview 25）；
- core 测试：`obj.rz=obj.time*360` 得到 540°、未触碰字段保持、跨块累加（90+10→100）、
  纯读取返回 `None`、`obj.zoom=2` 得到 200%、非数值不被应用；
- bake 测试 `a_text_script_can_rotate_the_object_for_the_frame`：10 fps 下第 5 帧
  `rotationZ=180`、第 0 帧 0、第 10 帧 360，且 `x=100` 未被影响；

### 7.40 B5（第三批）：对象列表按类型筛选

对象列表把当前帧的所有对象都列出来。一帧上叠了十几个对象时，想找某个文本或某个

| app | `workspace.rs` | `object_kinds_at_playhead()`：取当前帧对象类型去重排序，首项是空串（"全部"）；一个类型都没有时只有"全部"这一项 |

| ui | `timeline.slint`、`projection.rs` | `objects` 与 `object-rows` 分成两份：前者是滤波后的行，后者留给需要完整列表的调用；`object-kind-filters` 是本地化标签，`object-kind-filter-value` 是类型 id，两者分开存，避免"翻译变了就对不上" |

### 7.41 B5（第四批）：对象列表拖动改图层

对象列表按图层排序，所以"把一行拖到另一行"唯一说得通的语义是**改变图层**，而不是
改时间。本批补上这条命令与拖动交互，这也是 B5 的最后一项。

| 层 | 位置 | 改动 |
| --- | --- | --- |
| app | `workspace.rs` | `move_layer_objects_to_layer(source, target, maximum_layers)`：把源图层在该场景的**全部**对象移到目标层，帧与时长不动；目标层越界、已锁定、与源相同、源层为空都被拒绝并给出状态行；一次调用是一条撤销事务 |
| ui | `object-list.slint` | 行级 `pointer-event`：右键仍开共享菜单，左键按下记下源层，移动超过半行时按 28px 行高换算目标行，抬起时取该行对象的图层作为目标层 |
| ui | `timeline.slint`、`callbacks.rs` | 新增 `move-object-layer(source, target)` 回调，转给工作区并重绘三个窗口 |

语义与取舍：

- **移动整层而不是单行**：列表行代表"这一层在当前帧的这个对象"，但同层的其他对象
  仍在同一条时间线上；只搬一个对象会把一层拆成两半，所以整层一起走。
- **目标是"落点行所在的层"**：行数是对象数而不是层数，按行号算层号会算错，因此用
  抬起时那一行对象的 `layer` 作为目标。
- **拒绝优先于静默**：目标层锁定、越界、与源相同或源层为空都返回 `false` 并说明原因；
  锁定检查在 UI 侧命令里做，因为几何更新命令本身不带锁定语义。
- **一次拖拽一条撤销**：命令走 `execute_geometry_updates`，多对象时是一条
  `BatchUpdateClipGeometry`，测试里一次 `undo()` 即可回到原层。
- **不做跨层微调**：不提供"上移一层/下移一层"的菜单项，AviUtl2 的列表也没有该命令；
  需要精确调整时直接拖到目标行。

- `cargo test --workspace --all-features --locked` 通过（core 215、app 285、
  desktop 66、render 50、preview 25）；
- app 测试 `moving_a_layer_moves_all_of_its_objects_in_one_step`：移动后层号改变而
  起始帧不变、一次 `undo()` 复原、锁定目标层被拒、自移与越界被拒、空源层被拒；
- 离屏渲染对象列表确认拖动改造后行仍正常显示（下拉框与两行对象都在）；

### 7.42 B5.7（第二批）：场景复制重映射分组

§7.6 复制场景时原样复制片段的 `group` 字段，而分组 ID 是工程级：§7.8 之后一台工程里
可能有多个组，直接照抄会让副本里的对象与源场景的对象变成**同一个组**——点其中一个会

| 层 | 位置 | 改动 |
| --- | --- | --- |
| app | `workspace.rs` | `duplicate_scene` 在克隆片段时按源组建立映射，每组分配一个新的组 ID（从 `next_group_id()` 起递增），与 §7.8 的粘贴路径同一套做法 |

语义与取舍：

- **组结构与组 ID 分离**：副本内哪些对象同组保持不变，只换 ID；因此"复制一个分组
  场景"得到的仍是同样的分组关系。
- **每个源组一个新 ID**：用一张表按源 ID 记忆，两个源组不会在副本里被合并成一个。
- **不回写源场景**：映射只作用于被插入的副本，源场景的组 ID 不变。
- **仍是一步撤销**：组 ID 的改写发生在构造命令时，场景与全部片段仍在同一个事务里。

### 7.43 B3.8：命名色调色板（`<#name>`）

§7.3 内置了 10 个常用颜色名，但 AviUtl2 的色名来自用户的 `色設定` 调色板：每个色块可以

### 7.46 评估：画像合成（オブジェクト）

这是对照表里最后一个"待评估"。结论先行：**不新增独立对象**，理由与证据如下。

AviUtl2 手册（`usage.md`「画像合成（オブジェクト）」）的语义是四条：

1. 把下位图层上"作为合成目标的对象"合成一张图；
2. `対象レイヤー数` 指定下位图层的范围；
3. 合成对象本身画在目标图层的最下位；
4. 目标对象不再受组控制/相机控制，由合成对象承载这些控制。

「対象レイヤー数」在二进制里可以找到（UTF-16 字符串，与 `フレームバッファをクリア`
同组出现在对象参数名列表中，`0x2370??` 附近），说明它确实是对象参数而不是滤镜参数。

本仓库已有的 `frame_buffer` 已经覆盖了第 1 条的主干：`frame_buffer_scene()` 把下位图层的
`PreviewSource` 收进一个嵌套场景，作为帧缓冲对象的内容、带着它自己的变换与混合模式
绘制；`clearBelow` 控制是否遮住被合成的图层。也就是说"把下位图层合成成一张图再画出来"
这件事已经在管线里，缺的只是：

- **范围限制**：帧缓冲抓"本层之下全部"，没有层数上限；
- **绘制位置**：帧缓冲画在自己的图层，而画像合成画在目标范围的最下位；
- **控制归属**：帧缓冲不参与组/相机控制（它本身在 `is_control_object` 里），画像合成
  则要参与。

三处都依赖同一条前置事实：本仓库的图层编号方向与 Qt 版相反（`frame_buffer_scene` 按
`timeline_layer < 自身` 过滤，测试名为 `frame_buffer_captures_only_strictly_smaller_qt_layers`，
即"更小的编号 = 更靠前"），而画像合成的 `対象レイヤー数` 语义必须相对某一个确定方向
定义。在方向约定没有单独核实之前加一个对象，很可能让新对象与帧缓冲在同一个工程里
朝相反方向工作。

因此本批只记录评估，不实现：对照表该行改为「保留（由帧缓冲 + 组控制覆盖）」并注明
差异，留待有人真正需要"限定层数合成"时，先把图层方向约定核实清楚再动手。

## 8. 验收与风险

验收以可观察行为为准：标记在标尺上有清晰位置；前后跳转不越过场景时长；备注
编辑取消后不写入；撤销一次回到打点前；重开项目后标记还在；没有标记时菜单项
置灰而不是静默失败。

风险与对策：

- **文档兼容**：`marks` 用 `serde(default)` 读取，旧项目缺字段即为空；归一化层
  负责排序、去重与长度上限，避免坏文件把界面拖垮。
- **标尺拥挤**：标记只画在标尺上半部的小三角与 1px 竖线，不与刻度文字重叠；
  缩放很小时按像素合并。
- **撤销粒度**：一次"打点/删点/改备注"是一条事务，不与连续拖动合并。
- **备注编码**：备注按 UTF-8 原样保存，长度按字符数限制，不做本地化。

图层设置的验收以可观察行为为准：改名与改色后时间线立即更新；偏移同时出现在预览与
导出；相机目标层保持原坐标；音量 50% 时音频计划减半；一次 Apply 撤销一次即可回到
修改前；旧项目没有 `layerSettings` 字段时按空列表读取。

图层设置的风险与对策：

- **亮色背景压过对象**：行背景以 38% 透明度铺底，标题头只画 3px 色条，颜色不会
  盖住白色文字；用户仍可从设置里清空颜色回到主题背景。
- **相机与组控制的组合**：相机 `layerCount` 只用于判断偏移是否生效，相机本身的
  渲染范围仍是整场景；组控制与图层偏移按"先组后层"叠加。两者都记录在实现的边界里，
  后续做相机范围或剪裁对齐时一并修正。
- **数值与颜色输入**：表单按字符串接收，宿主统一夹紧数值、规范化颜色；颜色写错
  时对话框保持打开并给出错误，不会静默丢弃用户输入。
